# P52 — 어드민 완결 + 운영 배포

## 목표

람 지시: *"트레이너 프로필 사진 폰에 있는 거 넣을 수 있게. 어드민이니까 폴더에서 넣고 그런 거 되지 않나? 서버 작업도 하고 배포도 마음대로 해도 되니까 같이 진행해줘."* [P50](P50-admin-owner-usability.md)이 서버 작업 필요로 미뤄둔 2건(사진 업로드·운영시간)을 3계층으로 닫고, 오늘 쌓인 전부(P39~P51)를 운영에 배포한다. 지원 연락처는 람이 "사용자들끼리 아니까 괜찮다"로 종결.

## 결정 사항

- **사진은 서버가 올린다** — `storage.rules:90-95`가 이미 `staff/photos/**`를 "서버(Admin SDK)가 올리고 클라이언트는 토큰 URL로 읽는다"로 예약해 뒀다. 규칙 파일 **무변경**이 정답(클라이언트 직접 접근은 계속 차단).
- **축소는 브라우저에서** — 폰 사진 3~5MB를 그대로 보내면 서버 상한(2MB)에 걸린다. 캔버스로 512px·JPEG q0.85 (실측 3.18MB → **61KB**, 98% 감소). 투명 픽셀이 **실제로 있을 때만** PNG 유지 — 투명 로고를 JPEG로 접으면 검은 사각형이 되고 그 JPEG가 PNG보다 오히려 크다는 걸 실측으로 확인.
- **0시 문제**: 필드별 "0 = 부재" 관례(NormalizeHoldLimits)를 쓰면 **자정 개점이 영구히 표현 불가**가 된다. `Validate`가 `open < close`를 강제하므로 `(0,0)` 쌍만이 안전한 부재 서명 — 읽기는 관대(승격), 쓰기는 엄격(400).
- **서버는 운영시간을 강제하지 않는다** — 강제하면 대표가 21→20시로 줄이는 순간 이미 잡힌 21시 예약을 취소조차 못 하게 잠긴다(v2.0 소급 파괴 금지와 같은 근거). 어드민 격자도 **정책 ∪ 실제 슬롯**으로 그려 같은 사고를 막는다.
- **배포 순서 = 백엔드 → 어드민** — 반대면 어드민이 없는 API를 불러 404 안내를 띄우는 창이 생긴다(크래시는 안 나게 만들어져 있지만 굳이 만들 이유가 없다).
- **죽은 시크릿 제거** — P49로 코드가 안 읽게 된 `CHECKIN_QR_TOKEN`이 Cloud Run에 남아 있었다. 배포·검증 후 별도 op으로 제거(한 번에 섞으면 실패 시 원인 분리가 안 된다).

## 진행 단계

- [x] 서버: 정책 `open_hour`/`close_hour` + `POST /v1/staff/{uid}/photo`(Admin SDK 업로드·토큰 URL·옛 파일 정리) — 계약 v2.24·v2.25, [P51](P51-center-hours-staff-photo-upload.md)
- [x] 어드민: URL 입력칸 → 파일 선택 + 드래그앤드롭 + 브라우저 축소, 운영시간 폼·격자
- [x] 앱: 하드코딩 09~21 제거 → 정책값(부재 시 9/21로 오늘과 바이트 동일)
- [x] 3계층 통합 검증 + 로컬 E2E
- [x] **운영 배포**: Cloud Run `rize-api-00025` → 검증 → Hosting → 검증 → 죽은 env 제거(`00026`) → 재검증

## 변경 파일

서버·어드민·앱 상세는 [P51](P51-center-hours-staff-photo-upload.md) 및 각 에이전트 보고 참조. 오케스트레이터 직접분: 배포 실행·검증, Cloud Run env 정리.

## 검증

**배포 전** — 백엔드 584 PASS(-race·에뮬레이터 포함, 뮤테이션 33/35 kill + 2건 도달불가 증명) · 앱 **1,165 PASS**(뮤테이션 10/10, off-by-one은 첫/마지막 슬롯 키 직접 단언) · 어드민 빌드 그린. 로컬 E2E 7/7: 기본값 9/21 · 6~23 저장 · **다른 정책 필드 보존** · 역전 400(두 숫자 명시) · 업로드 미구성 503 · trainer 403 · `data:` 접두 400.
**교차 확인(오케스트레이터)** — 백엔드가 "`data:` 접두는 400"이라 했고 어드민 축소기가 실제로 접두를 떼는지(`blobToBase64`의 `slice(comma+1)`) 확인 / 업로드 후 폼 상태·기준선이 함께 갱신돼 **뒤이은 프로필 저장이 사진을 되감지 않음**을 확인(통 교체 PUT이라 놓치면 실사고) / Cloud Run에 `STORAGE_BUCKET`이 이미 있어 업로드가 운영에서 실동작함을 확인.

**배포 후 실측**
- 백엔드 `rize-api-00026-24l` 100% 트래픽. `/health` 200 · `/v1/public/business` 200 · `/v1/center` **401**(운영 인증 살아있음) · 신규 라우트 `checkin-qr`·`staff/{uid}/photo` **401**(404 아님 = 존재)
- 어드민 `https://rize-218c1.web.app` 200. 스크립트 자체 스모크 3종 통과(리라이트 순서·공개 API·인증 경계). **라이브 번들 grep**: 신규 문구 6종 전부 존재(체크인 QR 발급·사진 선택·첫 수업 시작 시간·다시 시도·재입사·인터넷 연결), **누수 4종 전부 0**(CHECKIN_QR_TOKEN·sha256sum·관리자에게·사진 URL)
- env 제거 후 재검증: health 200 · public 200 · checkin-qr 401 · Hosting 리라이트 200

## 후속 작업

- **회원 앱은 스토어 배포 필요** — 운영시간·계약서 본문 렌더·자필 서명이 전부 앱 번들에 있다. 배포 전까지 회원은 09~21시와 요약 고지 서명을 계속 본다(어드민이 이 사실을 화면에서 고지). [P46](P46-store-release-prep.md) 세션과 조율.
- 계약서 발행은 여전히 **대표 입력 2건 대기**(시설 신고 상태 선언 + 사업자 정보 12칸). 서버·어드민은 배포됐으므로 입력하는 순간부터 어드민에서 발행이 시작된다.
- 체크인 QR은 배포로 **미발급 상태**가 됐다 — 데스크에 붙은 종이가 있으면 무효. 어드민에서 [발급]→[인쇄] 2번 클릭 필요.
- `staff/photos/` 고아 파일 reconcile 부재(P51 기록), 센터명 하드코딩, 결정적 크래시 루프 2차 탈출구.
