## 목표

P12(결함 사냥)와 구분되는 **기능의 부재·껍데기** 전수 조사. UI는 있는데 뒤가 빈 것,
필드는 있는데 채우는 코드가 0인 것, 한쪽 계층에만 있어 완결이 안 되는 흐름, 문서·화면이
약속하는데 안 되는 것. **읽기 전용 — 소스 무변경.** 체형분석(bodycheck)·사진 표시·포즈는
다른 워크플로 진행 중이라 제외.

## 결정 사항

- 조사 편성: 병렬 3갈래(앱 5탭 / 어드민 전 화면 / 서버 라우트 58개 ↔ 클라 호출부 교차표) +
  운영 흐름(온보딩·결제환불·직원초대·생애주기)은 직접 추적.
- 불확실한 것은 DEV_SEED 로컬 서버(포트 8095)로 실측 후 종료.
- 우선순위 = 회원/대표가 부딪히는 빈도 × 막힘의 크기 (P0 당장 / P1 곧 / P2 나중).

## 검증 (DEV_SEED 실측, 포트 8095 — 종료 확인함)

1. **Pass 상태 전이 부재 확정**: `valid_until=2026-03-31`(5달 경과) 패스 생성 → `status:"active"`.
   `valid_from=2026-12-01`(미래) 패스 → `status:"active"`(scheduled 아님). 시드 포함 expired 0건
   → `GET /v1/stats` `rereg_d=0` — 재등록률은 프로덕션에서 영원히 분모 0.
   근거: `PassStatusExpired`/`Scheduled`를 **쓰는(대입하는) 코드 0곳** + 백엔드에 cron/ticker 0건.
2. **오탐 제거 — "동의 철회 비가역" 주장 기각**: 어드민이 `revoked_at`을 에코해 보내도 서버
   `UpdateMember`가 무시하고(`service.go:514-517`) false→true 전이에서 `revoked_at=nil`로
   정규화(`normalizeConsentTransition`). 철회→재동의 왕복 실측으로 확인.
3. **회원의 결제 조회**: `GET /v1/payments`를 member 스코프로 실측 — 본인 분할 내역이 내려옴.
   서버는 주는데 앱에 이를 그리는 UI가 0 (마이 탭 6블록에 결제 없음).
4. **발급 시 계약 자동 생성**: 패스 발급 → `sent` 계약 동반 생성 확인(`sha256`·`pdf_path`는 빈 값 — 기지).
