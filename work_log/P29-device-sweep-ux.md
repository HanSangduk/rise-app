# P29 — 실기기 전수 검수

## 목표

람: "앱에 기능 다 정상 동작하는지 그리고 ui/ux가 간격이랑 잘 맞는지 검수하고 개선해줘"

기기(Galaxy S21 Ultra, 1080×2400 / density 450 → **384dp**)로 전 화면을 훑고, 기기가
잠깐 끊겼던 동안에는 위젯 테스트로 같은 축(좁은 폭 · 최대 배율)을 대신 쟀다.

## 찾아 고친 것

### 1. 세션이 죽으면 로그인으로 돌아갈 길이 없었다 (기능)

`app_router.dart`에 TODO로 남아 있던 자리. `guardApi`가 **400대를 전부 `RejectedFailure`로
뭉개고** 있어서, 토큰이 폐기되면(다른 기기에서 탈퇴·계정 삭제) 회원은 모든 화면에서
"요청을 처리할 수 없어요"만 보고 **그게 규칙 위반인지 로그인이 끊긴 건지도 알 수 없었다.**

- 401만 `AuthFailure`로 분리 → dio 인터셉터가 세션을 비움 → `app.dart`가 로그인으로 복귀
- **403은 일부러 제외** — 신원은 멀쩡한데 권한이 없다는 뜻이라(담당 아닌 코치, 탈퇴 회원의
  잔여 호출) 그걸로 로그아웃시키면 정상 거절이 세션 종료로 번진다
- 토큰 갱신 자체는 Firebase SDK가 한다(`getIdToken()`) — 여기까지 401이 왔다는 건
  갱신으로 살릴 수 없는 상태다
- `null → null`은 무시한다(`prev != null` 조건). 없으면 세션 복원이 끝나기 전에 튕겨
  복원 자체가 죽는다

### 2. 촬영 화면이 포즈 8개에서 깨졌다 (P21이 만든 위험)

포즈를 트레이너 자유 입력으로 바꾸면서(v2.10) 서버 상한이 **8개 × 12자**가 됐다.
칩 `Wrap`이 여러 줄로 접히면 프리뷰(`Expanded`)를 0까지 밀고도 바깥 `Column`을 넘긴다.

실측(위젯 테스트, 실제 Pretendard 로드):

| 폭 | 배율 | 포즈 | 결과 |
|---|---|---|---|
| 320 · 360 | 1.0 · 1.35 | 기본 4 | OK |
| **360**(갤럭시) | **1.35** | **8** | **191px 넘침** |
| 320 | 1.0 | 8 | 170px 넘침 |
| 320 | 1.35 | 8 | **1436px 넘침** |

하단 컨트롤 존에 **화면 높이 42% 상한 + 스크롤**을 뒀다. 칩을 가로 한 줄로 바꾸지 않은 건
시퀀스 전체를 한눈에 보는 게 이 UI의 목적이라서 — 안 보이는 대신 스크롤로 닿게 했다.
상한을 42%로 잡은 이유는 프리뷰가 절반 넘게 남아야 이 화면이 하는 일(자세를 프레임에
맞추기)이 가능하기 때문이다.

### 3. 빈 상태 하나만 카드 밖 맨 텍스트였다 (간격)

기록 탭 "운동"에서 수업 기록이 없을 때만 카드 밖에 문장 한 줄이 떠 있었다. 같은 화면의
Home Work 주간 기록도, 다른 탭의 원장·예약·슬롯도 전부 카드 안에서 말한다.
`RiseCard` + `RiseCardHeader('수업 기록')`으로 골격을 맞췄다.

### 4. 인바디 차트를 읽을 수 없었다 (가독성)

색만 다른 두 선이 교차할 뿐 **어느 쪽이 근육이고 어느 쪽이 체지방인지 화면 어디에도
없었다.** 게다가 두 시리즈는 단위가 kg과 %라 **각자 범위로 정규화**돼 있어 선의 높이·교차점에
아무 의미가 없는데, 한 그림에 겹쳐 놓으면 회원은 반드시 비교해서 읽는다.

범례(●━ 골격근량 / ●━ 체지방률) + "선의 높이가 아니라 오르내림만 봐주세요" 한 줄을 붙였다.

## 실기기로 확인한 것

- **예약 플로우 E2E**: 슬롯 선택 → 확인 시트 → 확정 → 슬롯이 "내 예약 · 확정"으로 →
  홈 "다음 예약" 카드 반영 → 「내 예약」에서 취소 → 슬롯 복구
- **체크인 버튼이 이유를 말한다**: 비활성 + "셀프 체크인은 수업 시작 전후 30분에 열려요"
- **취소 다이얼로그가 정직하다**: 컷오프(24시간)를 지난 시점이라 "노쇼와 같이 세션 1회가
  차감돼요. 최초 1회는 유예되지만…" — 실제로 유예가 적용돼 **잔여 20회 그대로**였고
  이용내역에 감사 기록(0회)만 남았다
- **글꼴 배율 1.3**(안드로이드 최대) 전 화면 — 홈·기록·마이·촬영 모두 오버플로 없음
- **320dp 시뮬**(`wm density 540`) + 배율 1.3 — 촬영 화면 칩이 2줄로 접히고 안 넘침
- **서명 시트의 P28 수정분**: 계약가 1,000,000원 · 중도 해지 위약금 10% · "낸 금액이 아니라
  계약가 기준이에요" · 이용약관 전문 링크 — 배율 1.3에서도 전부 읽힘
- **회원탈퇴 화면**(실행 안 함): 되돌릴 수 없음 경고 · 잔여 20회 자동 환불 안 됨 경고 ·
  삭제 7항목(체형사진 원본 파일 포함) · 보관 항목 + 근거 법령/기간
- **약관 4행** 탭 → Chrome 실행 확인(페이지 내용은 호스팅 배포 후)
- **체형 분석 탭**: 8/23 실사진 렌더 · 포즈별 장수 칩
- **기기 설정 원상 복구**: `wm density 450` / `font_scale 1.0` 확인
  (⚠️ `wm density reset`은 600으로 되돌린다 — 이 기기는 명시적으로 450을 넣어야 한다)

## 오탐으로 기각한 것

- **예약 탭 "지남" 전부** — 11:04로 보였지만 기기 시각이 **23:05 KST**였다. 오늘 슬롯이
  전부 지난 게 맞다. 내일 날짜로 넘기니 정상 예약 가능
- **홈 우측 잘린 카드** — 삼성 엣지 패널 핸들(기존에 dumpsys로 확인한 건)
- **촬영 프리뷰가 검음** — 픽셀 (1,1,1)이 그라데이션 (67,70,79)와 달라 프리뷰는 정상
  렌더링 중이고 어두운 장면일 뿐(logcat AF 동작, 에러 없음)
- **나눗셈 기호가 `+`로 보임** — 원본 크롭 확대 결과 `÷` 정상(축소 아티팩트)

## 내 테스트가 헛돌던 것 두 건 (뮤테이션으로 잡음)

- **카드 간격 테스트가 항상 참이었다** — 인접 위젯 rect 사이를 쟀는데 `RiseCard`의 margin이
  위젯 자기 rect 안에 들어가 뭘 바꾸든 0이었다. 불변식(`margin == EdgeInsets.only(bottom: 10)`)을
  직접 단언하도록 다시 씀
- **칩 개수 단언이 프리뷰 상단 제목까지 셌다**(8 대신 9) — `PoseSequenceChips` 안으로 범위 한정
- **위약금 스냅샷 테스트가 정책·스냅샷을 둘 다 10%로 둬 구분 못 했다**(P28) — 5% vs 10%로 갈라 다시 kill

## 후속 작업

- **포즈 8개 실기기 확인 미완** — 회원 포즈 시퀀스를 8개로 바꾸려면 어드민 대표 로그인이
  필요하다. 위젯 테스트가 1436px 오버플로를 정확히 재현하고 수리 후 소멸하는 것까지
  확인했지만, 실기기 육안 확인은 람이 어드민에서 8개로 바꿔주면 이어서 할 수 있다
- **최초 노쇼 유예 1회 소진** — 취소 플로우 검증 때 실제로 사용됐다(차감은 0). 되돌리려면
  어드민 원장 조정이 필요하다
- 체크인 상태가 앱 재시작 시 사라짐(`CheckedInBookingId`가 메모리 전용) — 서버 Booking에
