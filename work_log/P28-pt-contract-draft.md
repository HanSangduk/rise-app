# P28 — PT 이용계약서

## 목표

람: "계약서 들어가 있는게 있는지 볼 수 있으면 좋겠다 (없으면 보내주겠음 ㅎ)" →
받기 전에 먼저 **법령 근거로 초안을 만들고**, 코드가 실제로 집행하는 것만 약속하도록 맞춘다.

## 결정 사항

### 근거 법령 — 확인한 것과 확인해서 **없앤 것**

| 근거 | 내용 |
|---|---|
| 방문판매법 제2조10호·제31조·제32조 | PT 회원권 = **계속거래**. 해지권은 약정으로 제한할 수 없다 |
| 공정위 고시 제2019-9호 [별표] | **헬스·피트니스업 위약금 = 총계약대금의 10%** |
| 표준약관 제10048호 | 「체력단련장 이용」 — 2025-05-23 개정으로 제1조에 "퍼스널 트레이닝을 포함합니다" 삽입 |
| 소비자분쟁해결기준 고시 제2025-14호 [별표2] | 이용료 = "계약 시 **납부한** 총 금액", 위약금 1/10 |
| 체육시설법 제10조①2·제22조 | 체력단련장업 = **신고업**(면적 하한 없음), 환급 3영업일·연 15% |
| 할부거래법 제2조·제8조·제16조 | 카드 할부 20만원 이상 → 7일 철회·항변권 |
| 전자문서법 제4조·제4조의2·제5조① | 전자계약이 서면으로 인정되는 조건 |
| 약관규제법 제8조 | `MaxPenaltyRate = 0.10`의 근거 |

**추측으로 인용하면 틀리는 두 가지**를 실제로 확인했다:
- 위약금 기준은 **시행령 별표가 아니라 공정위 고시**다.
- 흔히 인용되는 표준약관 **10023호는 전자상거래 약관**이고, 이 업종은 10048호다.
- PT 전용 표준약관은 **존재하지 않는다**.

### 코드의 실제 환급식(계약서가 이대로 말해야 한다)

```
per     = paid / total                              ← 정수 나눗셈(원 미만 절사, 회원에게 유리)
usage   = per × used                                ← used = 원장 complete + noshow 차감
penalty = min(int(paid × rate), int(paid × 0.10))   ← 하드캡
basis   = min(max(paidSum, 0), paid)                ← 실수납, 계약가가 상한
refund  = max(basis − usage − penalty, 0)
```

구조·횟수 비례·할인 후 단가·10% 상한 — **네 개 법정 기준 모두와 일치**한다.

### 안 쓴 조항 — 코드가 하지 않는 일

양도 수수료 · 유효기간 경과 시 소멸(만료 패스도 환불된다) · 자동 노쇼 · 자동 갱신 ·
사은품 정가 환수. 집행하지 않을 조항은 발행하지 않는다(`policy.go Validate` 주석의 원칙).

### 서명 전 조건 고지 결함 — 이번에 수리

계약서를 쓰다 드러난 것: `contract_sign_sheet.dart`가 **상품·결제금액·발송일 세 줄**만
보여주고 "위 계약 내용을 확인했으며 동의합니다"를 받고 있었다. **위약금율조차 없었다.**

회원이 본 적 없는 조건에 동의시킨 것이고, 방문판매법 제30조②(계약서 교부)의 필수
기재사항 누락이다(제63조2는 계약서 허위 기재를 형사처벌로 다룬다).

수리:
- 중도 해지 위약금 행 추가 — **계약 스냅샷 우선, 없으면 현재 정책**(서버 `refundBasis`와
  같은 순서). 다른 값을 그리면 "계약서 30% / 실제 공제 10%"로 갈렸던 사고의 재현이 된다
- "해지하면 이렇게 정산돼요" 박스 — 환불 공식·회당 단가·취소 컷오프를 서버와 같은 말로
- 동의 문구를 "위 계약 내용과 이용약관을 확인했으며"로 바꾸고 약관 전문 링크 추가

### 기초자를 밝히지 않은 "위약금 10%"는 거짓말에 가깝다

기초자를 안 밝히면 회원은 **자기가 낸 돈의 10%**로 읽는다. 분할 납부면 그 순간 갈리고,
회원은 정산서에서 처음 알게 된다. 세 자리를 고쳤다:

- **서명 시트·계약 상세**: "위약금(10%)" → **"계약가의 10% (낸 금액이 아니라 계약가 기준이에요)"**,
  금액 행 라벨도 "결제 금액" → **"계약가"**(어드민 v1.5 어휘와 통일)
- **어드민 환불 계산기**(`Sales.tsx`): 입력 라벨 "실결제 금액" → **"계약금액"**, 분할 시
  서버가 시작 금액을 실수납으로 잡는다는 사실을 안내에 명시
- **어드민 회원권 발급 폼**(`Members.tsx`) — **가장 위험했던 자리**. 같은 칸이 모드에 따라
  다른 값을 뜻하는데 라벨이 "실결제 금액" 하나였다. 발급이면 이 값이 `Pass.paid_amount` =
  **계약가**가 되어 회차 단가·위약금이 전부 여기서 나오는데, 분할이라고 1차분을 적으면
  단가·위약금·환불이 통째로 어긋난다. 라벨을 모드별로 갈랐다
  (발급 = "계약가" + 안내문 / 결제만 기록 = "결제 금액(실수납)")

## (D7) 위약금 기준액 — **확정: 계약금액 기준. 코드 무변경**

람이 "보통 계약금으로 하지 않나?"라고 물어 4갈래로 병렬 리서치(법령·고시 문언 / 분쟁조정·판례 /
표준약관·업계 실무 / 분할납부 특화)를 돌려 교차검증했다. **람 직감이 맞았다.**

핵심 근거 (상세는 `docs/계약서_PT이용계약_v1.md` §B-4 D7):
1. 방문판매법 제32조④가 위임한 **공정위 고시 제2019-9호**가 유일한 기준액 규범이고,
   제2조2호가 총계약대금을 "지급하기**로 한** 금액"으로 정의한다. 별표 = 헬스·피트니스업
   **총계약대금의 10%**. 2019년 이후 개정 없음(Open API로 `현행` 확인)
2. **같은 고시가 두 자리에 다른 단어를 일부러 쓴다** — 제5조①은 환급 모수로 "지급**한**
   계약대금". 지금 코드가 정확히 이 구조다
3. **실제 분할 납부 사례 2건**(1372 상담 55078·54190)이 계약금액 기준으로 답했다.
   60만 계약 중 20만 납부 → 위약금 6만(=60만×10%), 환급 14만
4. 공정위 2025-10 보도자료도 "총 계약대금의 10% 이내", 학계(고형석 2019)도 다툼 없이 그렇게 읽는다

**리서치가 잡아준 함정**: 법제처 「찾기쉬운 생활법령」의 "이미 납입한 이용료의 10%"는
**오래된 요약이고 고시 원문과 어긋난다**. "실거래금액/실 결제금액"은 기납부액이 아니라
**할인 후 실제 가격**을 뜻한다(소비자원이 문제 삼은 건 정상가 공제 관행). 카드 할부는
분할 납부 선례가 아니다(카드사가 전액 선지급).

**남은 위험 (없다고 하지 않는다)**: 소비자분쟁해결기준 문언이 2023-12-20 개정에서
"계약시 정한 실거래금액" → "계약 시 **납부한** 총 금액"으로 바뀌었고, 소비자기본법 시행령
제9조가 "소비자에게 유리한 기준 우선 / 소비자가 선택"을 규정한다. 게다가 고시 제4조①은
위약금이 별표 금액을 "**초과하지 못한다**" — **10%는 천장이지 정액이 아니다.**

→ **운영 권고**: 코드는 그대로 두고, **미납이 큰 상태의 해지**에 한해 대표가 위약금을 재량으로
낮출 수 있는 입구를 둔다(덜 받는 건 언제나 적법하다). 지금은 `RefundPass`에 그 입구가 없다.

**(D6) 위약금 0원/가산 환불을 계산할 수 없다** — `RefundPass(…, used int)`에 귀책 사유
입력이 없고 `SettleRefund`에 **더하는 경로가 아예 없다**. 청약철회(위약금 0)와 센터 귀책
(위약금 가산) 둘 다 손 정산이다. 조항은 법정 기준이라 남겼다.

**(D5) 청약철회 해당 여부 판정 불가** — `Contract`에 체결 경로가 없고 `Payment.Method`가
카드 할부와 일시불을 구분하지 못한다.

## 렌더링 권고 — (다) 버전 고정 템플릿 + 변수 스냅샷 + 해시

- `Contract`에 `TemplateVersion`("pt-v1")·`Vars map[string]string` 추가, **`send` 시점에 확정**
  (회원이 본 것과 서명된 것이 같아야 한다 — `FirstSentAt`이 비로소 의미를 갖는다)
- `sha256 = SHA-256(template_version + "\n" + canonical_json(vars))`를 `SignContract` 안에서
  계산해 봉인. 콘솔에서 값을 고치면 재계산이 어긋나 **검출된다**(지금은 고쳐도 아무도 모른다)
- 클라이언트 렌더를 배제한 근거는 **전자문서법 제5조①2**: `Pass.ValidUntil`은 일시정지마다
  바뀌고 `Policy`는 언제든 고칠 수 있어 "서명 당시 형태의 재현"이 구조적으로 불가능하다.
  `Contract.PenaltyRate`가 포인터 스냅샷인 이유(P14)의 반복이다
- PDF는 뒤로 — 제4조의2가 ①열람 ②재현 가능이면 서면으로 본다고 하므로 (다)만으로 교부가
  성립한다. PDF는 편의이지 적법성의 조건이 아니다
