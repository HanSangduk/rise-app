# P12 — 전면 감사 스윕

## 목표

P11(하드웨어 실연동)이 진행되는 동안, **아직 감사를 안 거친 영역**에 읽기 전용 감사팀 4개를
병렬로 붙여 구멍을 찾고 즉시 수정한다. 감사 대상은 이전 라운드들이 건드리지 않은 곳으로 골랐다:

| 팀 | 범위 | 방법 |
|---|---|---|
| 백엔드 | 결제·전자계약·홈워크·고정스케줄·체크인 | `DEV_SEED=true`로 8099에 서버 띄우고 **curl 실측** |
| 어드민 | Schedule · Members · Homework · BodyPhotos | 백엔드 요청 구조체와 **필드 단위 대조** |
| 인프라 | IAM·규칙 드리프트·시크릿·로그 PII·콜드스타트 | gcloud/REST **실측** |
| 앱 | 홈 · 예약 · 마이 · 기록 (P11 영역 제외) | 백엔드 도메인 소스와 **판정식 대조** |

## 결정 사항

### 감사를 실측으로 강제한 것이 결정적이었다
네 팀 모두 "코드를 읽고 추론"이 아니라 **실제로 실행**하게 했다. 그 결과가 갈렸다:

- 백엔드팀은 curl로 **환불 5,445,000원 지급**(정상 800,000원)을 실제로 재현했다. 코드만 읽었으면
  "상한이 없네" 정도로 끝났을 것이다.
- 인프라팀은 배포된 보안 규칙 소스를 REST로 받아 저장소 파일과 **바이트 단위 diff**해서
  드리프트 없음을 확인했다. "배포했으니 같겠지"가 아니라 확인이다.
- 인프라팀은 콜드스타트를 **24시간 로그에서 17회 실측**(380~525ms)해 "min-instances를 올려야
  한다"는 통념을 반증했다. uptime check가 2분마다 때려 인스턴스가 대체로 살아 있다.

### 자문자답 — 왜 이 결함들이 이제야 나왔나
이전 라운드들은 **읽기 경로**(권한 스코프, 마스킹, 상태 전이)를 반복 감사했고 거긴 실제로 촘촘하다.
남은 구멍은 전부 **쓰기 경로**와 **입력 검증**에 몰려 있었다 — 읽기는 "남의 것이 보이나"를 묻기 쉬운데
쓰기는 "남의 것에 쓸 수 있나"를 물어야 하고, 후자를 묻는 테스트가 없었다.

앱도 같은 구조였다. "권한·계산식"은 서버와 정확히 일치하는데(환불 계산기는 골든값까지 맞다),
**실패 처리**가 통째로 비어 있었다 — `catch (_) {}` 하나가 조회 실패를 "데이터 없음"으로 위장하고,
그 위장 상태에서 사용자가 저장을 누르면 진짜 데이터가 지워진다.

## 발견 — 심각도 순

### 돈이 새는 것 (백엔드)
- **C1 환불 지급액 배가**: 같은 패스에 결제 기록을 한 번 더 남기면 환불 기준액이 그대로 두 배.
  550,000원 패스에 5,500,000 기록 → 환불 견적 5,445,000. 어드민의 "결제만 재시도" 로직이
  서버 성공+응답유실을 구분 못 해 실제로 도달 가능하다. 되돌리는 API가 없다.
- **C2 일시불 결제 → 환불 0원**: `installments`가 비면 검증을 건너뛰는데 `PaidSum()`은 회차 기준이라
  0을 반환하고, 계약가 폴백은 "결제 레코드 0건"일 때만 작동한다. 전액 납부 회원에게 0원 환불하고
  패스는 `refunded` 확정. **결제를 정확히 기록할수록 손해가 커지는 역방향 인센티브.**

### 법적 기록이 남는 것 (앱)
- **C2 동의 무의도 철회**: 마이 탭 조회가 일시 실패하면 동의가 `false`로 위장되고, 회원이
  **토글을 건드리지 않은 채** 저장만 눌러도 서버에 `revoked_at`이 찍힌다. 회원이 철회라고 인지할
  행동을 한 적이 없는데 감사 기록엔 철회로 남고 민감정보 기능이 잠긴다.

### 조용한 데이터 손실 (앱)
- **H5 홈워크 완료 덮어쓰기**: 체크 조회가 실패하면 전부 미체크로 보이고, 그 상태에서 하나를
  토글하면 형제 항목 전체 배열을 POST한다. 서버는 `.Set()`으로 문서를 통째로 교체 →
  `[true,true,false]`가 `[false,false,true]`가 된다. 회원 본인도 인지 못 한다.

### 기능 자체가 죽어 있던 것 (어드민)
- **C1 홈워크 배정 항상 400**: 요청에 서버가 모르는 `excluded` 필드를 **항상** 실어 보내는데
  핸들러가 `DisallowUnknownFields()`를 건다. 어떤 입력으로도 성공 못 한다. 사용자는 같은 에러만
  보며 자기 입력을 계속 고치다 포기한다. 요청/응답 타입을 한 타입으로 겸용해서 컴파일이 통과했다.

### 권한 경계가 없던 쓰기 경로 (백엔드)
- **H1** `CreateWorkoutLog` — 회원 스코프 검사 자체가 없음. 다른 코치 회원에 기록 생성 200.
- **H2** `CreateHomework` — `target_member_ids` 무검증. 담당 경계 + **부상 자동제외(P39)** 동시 우회.
- **H3** `CreateHwCheck` — 검증 전무. 존재하지 않는 hw_id도 200, `date` 없으면 앱에서 체크가 풀려 보임.
- **M3** `Checkin` tap — 트레이너 담당 검사 없음. `CompleteBooking`·`NoshowBooking`은 하는데 비대칭.

### 인프라
- **H1** Cloud Run이 `roles/editor` 가진 기본 컴퓨트 SA로 **공개 호출 가능** 상태로 실행.
  SSRF/RCE 하나면 Firestore 전체 삭제까지 간다. → 전용 SA 필요(**IAM 명령이 정책에 막혀 미완**)
- **H2** `CHECKIN_QR_TOKEN`이 Cloud Run 환경변수에 평문 + 리비전 11개에 잔존. 검증이 평문 비교라
  만료·nonce가 없어 한 번 새면 무기한. 게다가 코드 기본값이 **동작하는 공개 토큰**이었다.
- **H3** Firestore 복구창이 **1시간**이고 백업 스케줄 0개.

## 이번 스윕에서 배운 것

### 실측을 강제한 것이 결정적이었다
네 감사팀 모두 "코드를 읽고 추론"이 아니라 **실제로 실행**하게 했다. 결과가 갈렸다 —
백엔드팀은 curl로 **환불 5,445,000원 지급**을 재현했고(코드만 읽었으면 "상한이 없네"로 끝났다),
저장계층팀은 에뮬레이터로 **동시 환불 2건이 둘 다 200**인 것을 재현했다(Memory에선 재현 불가라
`go test`로는 영원히 못 잡는다), 인프라팀은 배포된 규칙 소스를 받아 저장소 파일과 **바이트 단위
diff**했고 콜드스타트를 24시간 로그에서 17회 실측해 "min-instances를 올려야 한다"는 통념을 반증했다.

### 갭은 읽기가 아니라 쓰기에 몰려 있었다
이전 라운드들이 읽기 경로(권한 스코프·마스킹·상태 전이)를 반복 감사해 거긴 촘촘했다. 남은 구멍은
전부 **쓰기 경로**와 **입력 검증**이었다 — 읽기는 "남의 것이 보이나"를 묻기 쉽고 쓰기는 "남의 것에
쓸 수 있나"를 물어야 하는데, 후자를 묻는 테스트가 하나도 없었다.

### 계층 간 정합은 한 번 고치면 끝이 아니다
서버 원자성 수정(P13)이 `잔여 − 확정예약 > 0`이라는 새 거부 사유를 만들었고, 그 순간 앱이
**100% 거부될 버튼을 다시 띄우는 상태**가 됐다(P14로 즉시 닫음). 한 층을 고치면 다른 층이
어긋나는지 그 자리에서 확인해야 한다.

### 문서도 코드처럼 썩는다
README 세 개가 "스캐너 미도입"·"수평계는 시뮬로 대체"·"storage_path는 스텁"이라고 적고 있었는데
전부 거짓이 돼 있었다. 어드민의 고정 스케줄 삭제 확인 문구는 **서버 동작과 정반대**를 단정하고
있어서(v2.3에서 미래 예약을 함께 취소하도록 바뀐 걸 반영 못 함) 대표가 "예약은 남는다"를 믿고
누르면 회원 예약이 통보 없이 사라지는 상태였다 — 문서 대조 중에 발견됐다(P15).

### 검증 도구가 검증 대상보다 먼저 거짓말한다
실기기 하네스가 네 번 속였다(P11에 상세). 넷 다 "화면은 찍히고 오류 없음"으로 끝나는 형태였다.
**결과를 열어보지 않으면 도구의 성공을 대상의 성공으로 착각한다.**

### 근거를 추정 위에 세우면 심각도가 틀린다
P16이 "예약 탭 지남"의 근거를 *서버도 지난 슬롯을 받아 준다 → 노쇼 차감*으로 적었는데,
`CreateBooking` 첫 검증이 실제로는 막는다(`start.Before(time.Now())` → 400). 고친 것 자체는
유효했지만 심각도는 돈이 아니라 헛클릭이었다. 근거를 그대로 뒀으면 다음 사람이 "서버에 지난
시각 가드가 없다"고 믿고 엉뚱한 곳을 팠을 것이다 — **클라이언트 결함의 심각도를 서버 동작
추정 위에 세우지 말 것.**

## 운영 실인증 검증 (읽기 전용)

Firebase 테스트 전화번호로 **실제 회원 ID 토큰**을 발급받아 배포된 API를 직접 두드렸다.
소스 판독이나 로컬 실측이 아니라 **운영에서 실제로 그렇게 동작하는지** 확인한 것들:

- `/v1/me` → `role=member`, `name=김민지` (v2.2 표시 이름 정상)
- `/v1/center` → `penalty_rate 0.1` (v2.7 상한 적용 후), `revenue_target`은 회원에게 0으로 비워짐
- `/v1/passes` → v2.6 정렬 규약 적용
- `/v1/homeworks?date=2026-13-45` → **400** `"date는 YYYY-MM-DD 형식이어야 해요"`
- `/v1/staff` → `offdays`가 **회원에게 실제로 내려온다**(앱 휴무일 판정의 전제 — 앱 주석이
  "생략된다"고 잘못 적고 있었다), `payout`은 `{"type":"","value":0}`으로 비워짐
  ⚠ 필드가 **존재한다**는 것만 보고 유출로 판단할 뻔했다 — 값을 열어봐야 한다.
- 앱에서 실제 예약 생성 → 서버에 `20260823-19 confirmed` 반영 확인

**위약금율 CRITICAL은 운영에서 발현된 적이 없다** — 정책이 계속 기본값 10%라 세 자리가
우연히 일치했다. 대표가 그 값을 한 번이라도 바꿨으면 갈라졌을 것이고, 잘못된 조항이 박힌
계약서는 아직 없다.

## 후속 작업

### 람이 직접 해야 하는 것 (권한이 막혀 내가 못 함)
1. **Cloud Run 전용 SA 교체** — IAM 명령이 도구 정책에 막혔다. 기본 컴퓨트 SA의 `roles/editor`가
   공개 엔드포인트의 런타임 권한이라 가장 큰 폭발 반경이다.
   ※ 주의: 이 SA는 buildpack 배포 시 Cloud Build도 쓴다. 런타임 SA만 먼저 교체하고
   editor 제거는 배포가 깨지지 않는지 확인하며 나중에.
2. **`CHECKIN_QR_TOKEN` Secret Manager 이전 + 로테이션** — 리비전 11개에 값이 박혀 회수가 안 된다.
   QR 스캐너가 붙으면 토큰이 앱에 심기지 않고 QR에서 읽히므로, 로테이션이 "시크릿 갱신 + 데스크 QR 재인쇄"로 끝난다.
3. 중기: 평문 비교 QR → **HMAC + 타임스탬프 서명**으로 전환(현재는 한 번 새면 무기한 유효)

### 남은 항목
- `maxScale 20` → 3~5 (단일 센터 규모, 공개 엔드포인트라 폭주 시 청구가 는다)
- 예산 알림을 모니터링 채널에 연결(현재 `notificationsRule: {}` — 결제 관리자 메일로만 감)
- 프로덕션 `CORS_ORIGINS`가 localhost뿐 (Hosting rewrite로 same-origin이라 동작엔 무해하나 냄새)
- 컨테이너 취약점 스캔 비활성
- 사진이 버킷에 쌓인 뒤 객체 ACL 재점검(지금은 객체가 사실상 없어 검사 대상이 없었다)
