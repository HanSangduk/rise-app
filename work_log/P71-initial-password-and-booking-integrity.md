# P71 — "비밀번호가 없어서 문제"에서 시작해 예약 무결성까지

## 목표 (람 요청)
1. 센터 등록 시 대표 계정에 **기본 비밀번호를 설정**하고 화면에 적어라. 대표가 로그인해서 바꾸면 된다.
2. "이런 불편한 로직들이 많을 것 같은데" — **자율로 전면 검수** + 교차검증 + 자문자답 반복.
3. 각 에이전트에 맞는 모델을 할당해 병렬로.

## 팀 구성 (1단계)
- 백엔드 온보딩 마찰 검수(opus) · 어드민 여정 검수(opus) · 앱 온보딩 검수(sonnet) — 전부 읽기 전용
- 실행 단계에서 어드민 수정(opus) · 앱 수정(opus) 2팀 추가 투입, 백엔드는 내가 직접

## 교차검증 (2단계) — 확정 / 오탐

### 확정: 프로덕션 예약 정원이 강제되지 않고 있었다 (CRITICAL, 이미 배포됨)
`store/firestore.go` `BookAtomic`이 `domain.CanBook`을 **호출하지 않았다**. 머리 주석은 처음부터
"슬롯 읽기 → CanBook 판정 → 예약 생성"이라 적혀 있었고 판정만 없었다. 호출은 `memory.go`에만
있었고 전 테스트가 Memory를 타서 초록불이었다.

에뮬레이터 실측으로 **버그와 수정을 둘 다 증명**했다(수정 제거 → 실패 재현 → 복구 → 통과):

| | 코치 중복 | 회원 중복 | 정원 초과 | 슬롯 팀 수(정원 3) |
|---|---|---|---|---|
| 수정 전 | 통과 | 통과 | 통과 | **6** |
| 수정 후 | ErrTrainerBusy | ErrMemberBusy | ErrSlotFull | 3 |

기존 커버리지가 비껴간 이유: 예산 테스트들이 goroutine마다 **다른 slotKey**를 써서 슬롯 규칙은
건드리지 않았다. `BookAtomicEnforcesSlotRules` 컨포먼스 서브테스트 신설.

### 확정: 새 센터 대표는 로그인할 방법이 0이었다 (람의 원 보고)
백엔드는 난수 비밀번호를 걸고 "초대 메일은 어드민 프론트가 보낸다"는 규약을 뒀는데, 그 규약을
지키는 화면은 **트레이너 초대 하나뿐**이었다. `Centers.tsx`에는 `sendPasswordResetEmail` 호출이
아예 없고 "안내하세요"라는 문장만 있었다. 두 검수팀이 독립적으로 같은 결론.

### 오탐 (되돌림): 같은 번호 중복 등록 차단
"승인 경로엔 409가 있는데 데스크 등록엔 없다"는 비대칭이 결함으로 올라왔고 실제로 409를 넣었다.
테스트 6건이 깨지며 드러난 사실 — **부모 번호로 자녀 둘 등록은 이 저장소가 의도적으로 지원한다**
(`betterPhoneMatch` 주석 + 전순서 규칙 + 전용 회귀 테스트). 철회하고 근거를 코드 주석에 남겼다.

### 오탐 (되돌림): 전화번호 저장 정규화
저장을 숫자만으로 바꾸려다 철회 — 두 스토어가 **비교 시점에 양쪽을 정규화**하므로 저장 형식은
매칭에 영향이 없고, 바꾸면 기존/신규 문서 표기만 갈린다. 자릿수 검증만 정규화 값으로.

## 실행 (3단계)

### 백엔드 (직접)
- `config`: `InitialStaffPassword`(env `INITIAL_STAFF_PASSWORD`, 기본 `123456`) + **6자 미만 기동 거부**
  — Firebase Admin SDK가 6자 미만을 로컬 검증으로 거부한다(`auth/user_mgt.go:639`). 람이 말한 "1234"는 물리적으로 불가능.
- `provision.go`: `EnsureUser`가 `created bool`을 함께 반환 → **새 계정에만** 비밀번호를 안내한다.
  난수 `tempPassword()` 제거(이유는 주석으로 남김).
- `service_admin.go` `CenterCreated.InitialPassword` · `service.go` `StaffCreated`(*domain.Staff 임베딩 → 와이어 평면 유지)
- `firestore.go` `BookAtomic`에 `domain.CanBook` 추가
- `domain/member.go` `Normalize()`·`Validate()` 신설, `CreateMember`·`UpdateMember`(스태프 경로)에서 호출
- `guardNotStaff` fail-open → fail-closed(`ErrNotFound`만 부재로 접는다)
- `domain.Staff.Email` 신설 + `ListStaff` 마스킹(owner 전원 / trainer 본인 / member 없음) —
  "트레이너가 로그인이 안 돼요"에 대표가 등록 이메일을 확인할 수단이 없었다. 회원 앱 코치 소개가
  같은 응답을 읽으므로 마스킹이 필수. 종전 계약(응답에 email 금지)을 뒤집은 것이라 그 테스트도 다시 썼다.

### 어드민 (내 영역 + 에이전트)
- 신설 `InitialPasswordNotice.tsx` — 이메일·비밀번호·복사 버튼·"바꾸라"는 경고. 계정이 이미 있던
  경우엔 **비밀번호를 지어내지 않고** 다른 문장을 그린다.
- `Centers.tsx`: 생성 후 `sendPasswordResetEmail`까지 보내고(메일 실패는 생성 실패로 되돌리지 않음),
  완료 카드에 최초 비밀번호 노출. 대표 이메일을 폼에서 올려 받는다(서버 응답에 email이 없다).
- `Settings.tsx` 초대 결과에도 동일 안내. `types.ts`에 `Contract.template_version` 정식 편입.
- 에이전트 10건: 승인/거절 중 창 잠금(CRITICAL) · 계약 본문 미발행 배지와 문구 정정 · 손등록 후 다리 ·
  첫 회원권 라벨 · 노쇼 waive 오해 · 템플릿 덮어쓰기 2단 확인 · 전 회원 배정 확인 · 모바일 grid ·
  빈 상태 문구 · 예약 모달 잔여/코치 중복 사전 판정

### 앱 (에이전트)
- 카메라 권한 영구 거부 후 **설정에서 켜고 돌아오면 스스로 복구**(체형 촬영·QR 둘 다). 일시 거부는
  일부러 제외 — 복귀할 때마다 부르지도 않은 시스템 팝업이 뜨는 쪽이 더 나쁘고, 그 상태엔 살아 있는
  버튼이 있어 갇히지 않는다.
- 저장 왕복 중 이탈 차단(`canPop`·`_handleClose` 조건 일치) + await 뒤 `ref.mounted` 가드 —
  폐기된 ref에 state를 쓰면 갱신이 아니라 **던진다**.
- 세션 종료 시 열린 바텀시트 자동 정리: 개별 시트가 아니라 `rise_sheet.dart` 래퍼 한 곳에서.
  `Navigator.pop()`으로 단정하지 않고 **자기 라우트를 집어** 처리한다(시트 위 확인창이 대신 닫히는 사고 방지).
- 백그라운드 전환 시 카메라 실제 해제(구독이 0이 되지 않던 watch 한 줄).
- 코치 카드 "탭해서 다시 시도"가 실제로 재조회하도록.

검증: `flutter analyze` 이슈 0 · `flutter test` **1477 pass**(기준선 1465, 신규 12·회귀 0).
각 수정은 해당 줄을 되돌리면 죽는 것까지 확인했다.
