# P30 — 홈 개선

## 목표

람: "앱 홈이 너무 허전한데 예약이 없으면 예약하러 가기 버튼 같은거 눌러서 예약 탭으로
이동한다던가, 트레이너 프로필 보기라던가 — 홈에서 트레이너 찾고 예약도 편하게 하고
그런 부분들이 들어가야하지 않을까"

기획 3팀(회원 여정 / 경쟁 제품 / 미사용 역량)을 병렬로 돌리고 교차검증했다.

## 리서치 결론 — 12개 제품을 조사해서 나온 두 가지

**① 홈을 예약 표면으로 쓰는 곳이 사실상 없다.**
Trainerize(로깅과 섞인 "+" FAB) · TrueCoach(예약 없음) · Everfit(Coaching→Sessions→View all
두 단계 아래, 기본 OFF) · PT Distinction(예약 없음) · Mindbody(Book 탭) · ClassPass(Search 탭) ·
Momence(Schedule 링크) · Walla(Schedule 탭) · Mariana Tek(Schedule) · Glofox(Schedule) ·
Zen Planner(캘린더가 곧 홈) · WellnessLiving(**유일하게 삭제 불가 Book 탭**, 단 홈 자체가
기본 OFF). **즉 홈에 예약 진입점을 두는 건 업계 공백이다.**

**② 코치를 홈에 세운 곳은 하나도 없다.** 그런데 국내 회원 리뷰에는 그 공백이 그대로
불만으로 있다 — 하이파이브: *"어떤 코치님이 참여하시는지 적혀있으면 좋겠어요"*,
*"담당 코치/트레이너와 앱 내에서 소통할 수 있었으면 좋겠습니다. 개인카톡으로 소통할 경우에
양방향에서 불편할 수 있는 상황이 발생할 수도"*. 코치와의 연결이 앱 밖(카톡·밴드)으로 샌다.

### 검증된 패턴은 하나뿐 — Mindbody의 "빈 카드마다 자기 CTA"

*"If you don't have any classes currently booked, tap the **Explore** button to access the
business's class schedule."* — 같은 문장을 홈과 프로필 두 곳에 **똑같이** 쓰고, 빈 회원권에는
**Buy**를 쓴다. 빈 컨테이너마다 그에 맞는 카탈로그로 가는 로컬 CTA를 하나씩 붙이는 방식이다.

### 안 한 것 — 시장이 직접 답을 줬다

짐박스(4.78★) 리뷰: *"이 어플의 본질은 '헬스장 이용권 바코드' 입니다. **자꾸 이것저것 기능
넣어서 쓰기 불편하게 만들지 말아 주세요.**"* 스튜디오메이트 호평도 같은 방향 —
*"불필요한게 없어서 좋아요"*, *"쓸데없는 광고가 없어서 좋으네요"*.

→ **게임화(성취·배지·랭킹)·광고·커뮤니티 피드는 넣지 않았다.** 허전함의 답은 "더 얹자"가
아니라 **"있는 것에 문을 달자"** 다.

## 고친 것

### 1. 빈 「다음 예약」이 막다른 길이었다

종전: `'이 회원권 담당 코치로 예정된 예약이 없어요 — 예약 탭에서 잡아보세요'`
**가라고 말하면서 버튼이 없었다.** 프로덕션 회원 실측(예약 0 · 결제 0 · 수업기록 0)에
대입하면 홈에 누를 수 있는 요소가 **0개**였다 — 람이 본 화면이 바로 그것이다.

→ `[예약하러 가기]` 전폭 버튼. 범위 안내("이 회원권 담당 코치로")는 남겼다.

### 2. 탭 이동 수단이 앱에 아예 없었다

`goBranch`는 `AppShell._go` 하나뿐이고 private이었다. 그래서 `'예약 탭에서 잡아보세요'`,
`'…(예약 탭)'`, `'촬영 탭에서 첫 사진을 남겨보세요'` 가 **탭 이름을 부르지만 보내주지 않는
문장**들이었다.

→ `core/router/tab_navigation.dart` — `AppTab` enum이 브랜치 인덱스의 단일 출처.
`goBranch(initialLocation: false)`로 **탭 상태를 보존**한다(예약 탭에서 고른 날짜가 남아야
한다). 셸 밖(위젯 테스트)에서 부르면 조용히 무시 — 카드 하나 띄웠다고 예외로 죽는 것보다 낫다.

### 3. 담당 코치 카드 (신규)

`GET /v1/staff`는 **홈 로드의 첫 호출**이고 서버는 회원에게 사진·직함·연차·전문분야·자격·
수상·소개를 **전부** 내려준다. 그런데 홈은 여태 `name` 하나만 썼다. 프로필 시트도 이미
있고 네트워크 0이다 — **새 요청도 새 서버 작업도 없다.**

빈 프로필의 이유 세 갈래를 뭉치지 않는다(프로필 시트와 같은 규약): 캐시 미로드는
"불러오지 못했어요 — 탭해서 다시 시도", 현직 미등록은 줄 자체를 만들지 않음(빈 줄이 남으면
"불러오다 만" 것처럼 보인다), 퇴사는 배지.

전문분야는 **3개까지** — 그 이상은 카드가 프로필 시트를 대신하려 든다.

**마켓플레이스식 "코치 고르기"는 만들지 않았다.** `POST /v1/bookings`는 트레이너를 받지 않고
`Pass.trainer_id`가 정한다 — 목록을 보여주면 바꿀 수 있다고 오해시킨다. 게다가 이 센터의
트레이너는 현재 1명이다.

### 4. 다음 예약에 날짜가 없었다

`DateFmt.hhmm`만 써서 `"09:00 · 1:1 PT"`가 전부였다 — **'오늘' 배지가 없는 순간 회원은 그게
내일인지 다음 주인지 홈에서 알 방법이 없었다.** 그러면서 바로 아래 줄은 헤더가 이미 말한
센터명을 반복하고 있었다. 오늘이 아니면 `8/27 (목) 09:00`으로 날짜를 붙인다.

### 5. 헤더의 죽은 화살표

센터명 옆 `chevronDown`이 드롭다운처럼 생겼는데 `const FittedBox` 안이라 **탭 핸들러조차
없었다.** 이 앱은 센터가 하나고 전환 기능이 없다. 제거했다(마이 탭의 "다른 센터 가입 요청"을
같은 이유로 이미 뺐던 것과 같은 판단).

### 6. 회원권 배지가 항상 켜진 경고 + 없는 경로를 가리켰다

`잔여 N회 — 연장 상담 가능`이 **조건 없이 항상** 노란 경고였다. 둘 다 문제였다:
① 늘 켜져 있으면 정작 D-3에 아무 신호도 못 된다 — 경고가 배경이 된다.
② "연장 상담 가능"은 회원이 앱에서 갈 경로가 없는 약속이다(재등록·상담 요청
엔드포인트가 서버에 없고 `POST /v1/passes`는 회원 403).

임계값은 **센터가 정한 `policy.expiring_days`**를 쓴다. 서버는 v1부터 이 값을 내려주고
있었는데 **앱이 파싱조차 하지 않아** 임계값을 아예 갖고 있지 않았다 — DTO·모델·provider를
끝까지 연결했다. 앱이 임의 상수를 쓰면 대표가 설정에서 바꾼 기준과 회원이 보는 경고가
갈린다(어드민 대시보드의 "만료임박" 목록도 같은 값을 쓴다).

규칙: 유효기간 초과 → "유효기간이 지났어요" / 임박 → `D-N · 잔여 M회` / 잔여 0 →
"잔여 회차를 다 썼어요" / 잔여 3 이하 → "잔여 M회 남았어요" / 그 외 → **아무 말도 안 한다**.
**행동을 지시하지 않는다** — 없는 경로를 가리키느니 사실만 말하고 데스크에 맡긴다.

실기기 확인: D-88·잔여 20회에서는 배지가 사라지고, 어드민에서 기준일을 120일로 올리자
`D-88 · 잔여 20회`가 켜졌다(확인 후 7일로 원복).

### 7. 결제 카드가 거짓 날짜를 찍고 있었다 (P26에서 내가 만든 버그)

완납 회차에도 `due`(예정일)를 "납부일"이라 찍었다 — 예정 9/1에 실제 9/14에 낸 회원 화면에
**9/1이 자기가 낸 날로** 떴다. `paidAt`을 쓰도록 고쳤다. 청구 종결(환불)은 낸 것도 낼 것도
아니라 "예정일"이라고 부른다.

## 오탐으로 기각한 것

**빈 회원권 화면의 `[새로고침]`이 죽은 버튼이라는 지적** — 기획팀이 "발급은 스태프 전용이라
회원이 몇 번 눌러도 안 바뀐다"고 올렸는데, 코드를 확인하니 `onRefresh`가
`homeViewModelProvider`를 무효화해 **서버에서 다시 받아온다**. 가장 흔한 시나리오가
"회원이 데스크 앞에 선 채로 대표가 회원권을 발급하는 순간"이고, 그때 이 버튼이 정확히
맞는 행동이다. 문구도 이미 그 순서를 말한다("센터에서 회원권 등록 후 이용할 수 있어요").
바꾸지 않았다.
