# 인바디 결과지 OCR 프리필 — 실측·이식 사양 (P20)

회원 앱 "사진에서 채우기"의 근거 자료. 람이 준 실물 결과지 5장(`~/Downloads/inbody/`)으로
파싱 규칙을 실측·정련한 결과다.

## 실측 결과 (2026-08-23, macOS Vision 엔진)

| | 체중 | SMM | BFM | PBF | VFL | BMR | 날짜 |
|---|---|---|---|---|---|---|---|
| sheet1 (InBody270) | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| sheet2 (구형 BR-KOR-40) | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| sheet3 (LookInBody 모니터 촬영) | ✓ | ✓ | ✓ | 빈칸 | 장에 없음 | 장에 없음 | 장에 없음 |
| sheet4 (InBody270, 실사진) | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| sheet5 (구형, **비스듬히 촬영**) | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | 장에 없음 |

**정확 30 · 안전한 빈칸 1 · 틀린 프리필 0** (채울 수 있는 31칸 기준)

핵심 속성은 마지막 열이다 — **확신 없으면 빈칸**. 틀린 값이 채워지면 회원이 그대로 저장하지만,
빈칸은 결과지를 보고 채운다. 검증(R11)이 버린 값은 전부 빈칸이 된다.

## 파일

- `parse.py` — 규칙 전체가 헤더 독스트링(R1~R11)에 있고, 각 규칙에 "인바디 결과지의 구조적
  근거"가 붙어 있다. **이 파일이 Dart 이식의 사양서다.** 특정 장 좌표 하드코딩은 없다.
- `ocr.swift` — 실측에 쓴 macOS Vision 하네스(이미지 → 토큰 TSV)

## 정련 중 실측된 함정 (이식 시 회귀 테스트로 만들 것)

| 함정 | 규칙 |
|---|---|
| "적정체중 67.6"이 체중 앵커에 걸림 | R1 완전일치 |
| 신체변화 히스토리의 과거값 열 | R2 |
| 비스듬한 사진에서 옆 행 값 혼입 (smm←bfm 15.3 실측) | R3 기울기 + R7b 행 소유권 |
| 바 눈금(55,70,85…) 오픽업 | R4 타입 강제 + R6 "범위 없는 같은 줄 숫자 절대 불채택" |
| 제지방량 62.5 → BMR/BFM 혼입 | R4(BMR 정수) + R1(체/제 배제) |
| "35.2"에 바 글리프가 붙은 "135.2" | R9 선행 1 제거 + R11 항등 재시도 |
| 비만도 117% → PBF 혼입 | R4 소수 강제 |
| 권장섭취열량 2166 → BMR 혼입 | R7b 행 소유권 |

## ML Kit 이식 주의

- ML Kit도 토큰+바운딩박스를 주지만 **좌표계가 다르다**(픽셀, y 아래로 증가) — 정규화 후
  y축 반전해서 규칙을 그대로 쓰거나 부등호를 뒤집을 것.
- 토큰 분할 습성이 Vision과 다르다 — R9(소수점 복원)와 R6의 "바로 오른쪽 토큰의 범위" 결합은
  라인/엘리먼트 단위를 오가며 재현해야 한다. ML Kit의 `TextLine`/`TextElement` 양쪽을 쓸 것.
- 한국어는 기본 모델에 없다 — `google_mlkit_text_recognition`의 Korean 스크립트 옵션 필수
  (Android는 스크립트별 네이티브 라이브러리가 추가된다).
- 엔진이 다르므로 **이식 후 이 5장으로 기기에서 재실측**해야 한다(기기 갤러리에 넣어 둠:
  `/sdcard/Pictures/inbody_sample_*.jpg`). Vision 점수는 상한 참고치이지 보증이 아니다.

## 제품 결정 (docs/API계약_v1.md v2.9와 정합)

- 자동 저장 없음 — 프리필 후 사람이 확인하고 저장. 결과지 이미지는 저장·전송하지 않는다
  (기기 안에서 숫자만 뽑고 버림 — 결과지엔 이름·나이·성별이 함께 인쇄된다).
- 서버 비용 0 (온디바이스), `storage.rules` 무변경.
